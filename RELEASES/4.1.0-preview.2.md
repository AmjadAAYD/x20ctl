# X20ctl 4.1.0 Preview 2

Download **x20ctl.exe** and run it directly on Windows x64. The scanner is built into the executable. Microsoft WebView2 Runtime is required; the executable is unsigned.

## Input support and configuration limits

- D10, X15, X05 and X10 now have experimental input Studios with explicitly selected Windows XInput sources, player ownership and model-specific Known/Missing information. X15 also retains its strictly matched candidate HID input layout.
- D10 receiver 2345:E062 is recognized from published receiver evidence. X15 receiver 1A34:F517 remains experimental. Generic 045E:028E and shared 0079:181C never uniquely identify an EasySMX model.
- **Persistent button remapping, macro programming and advanced configuration remain disabled for D10/X15/X05/X10.** Input testing is not remapping. Their model-specific command payloads, ACK/readback and physical acceptance are still missing.
- X20 retains its existing configuration backend. Explicitly named non-X20 configuration peripherals are now rejected before entering its writer. X20 Pro and X05 Pro retain preview/research status.

## Built-in scanner improvements

Repeated button/rear-input comparisons, cleared/A/B macro-output tests, long/short trigger-mode comparisons, smooth sweeps, optional documented-mode identity collection and short opt-in standard XInput vibration tests are included. The motor API does not write stored strength settings or independently control trigger motors.

X15/KeyLinker and X10/QMacro discovery clues support GATT metadata collection with dynamic handles; they authorize no vendor commands. Owners can record an already-working app's baseline/change/readback/disconnect/power-cycle/restore timeline. Firmware/revision/app context can be associated with selected USBPcap, Windows HCI PCAP/PCAPNG or Android BTSnoop imports. Capture containers are validated; commands and target identity are not automatically decoded or verified. No capture driver, firmware flashing, arbitrary vendor writes or RGB workflow is added.

Reports require collection consent and review. Automatic X20ADMIN submission still awaits the compatible receiver deployment; reports can be saved locally and shared manually.

## Verification

294 focused backend tests, TypeScript check, Vite build and eight isolated headless flow groups passed during implementation. The versioned executable's internal worker and embedded source/assets are checked before publication. These are software checks, not physical-controller acceptance. Native GUI acceptance, live input/motor testing and actual protocol traces were not performed. This remains a prerelease; 4.0.1 remains the stable release. No Linux binary is included.

# Screen golden fixture provenance

These are synthetic research inputs and output bytes generated by the original DIYTool v1.0.3 in the isolated 1 November 2026 execution. They contain no vendor executable, DLL, MCU firmware or manufacturer artwork. The vendor EXE SHA-256 is 6973a67ba869da74cc917cae72a6893a6e09699e4e53ecff22e9083bd2124ad5.

The parent research captures are `audit/DIYTool-reconstruction-2026-10-29/ground-truth/outputs`. Names match case folders. RGBA files are decoded vendor-cropped pixels, row-major RGBA; animation frames are concatenated. `.bin` files are actual vendor assets, `.metadata` contains the captured 4096-byte metadata. `large-first.lt` and `.rgba` are the first frame of the 234-frame boundary case.

Packet fixtures come from actual original QIODevice::write calls: handshake and first-data/CRC from gradient upload, connect-first from connection opening, and vendor-upload.frames/vendor-reset.frames from complete captured transactions. Time-dependent handshake nonces are normalized only when comparing full sequences. Synthetic replies are not physical-device evidence. See the research report for harness details and limits. SHA256.json records each binary input/output hash.

`compressed-*` vectors come from the separate `ground-truth/compression-edge-outputs` original-tool runs with PICZIP:1. These are compressed still files with 12-byte descriptors; tests compare their LT payload with the shared animation compressor. Red/green odd-padding cases distinguish retained raw bytes from zero fill.
